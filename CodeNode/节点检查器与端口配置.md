# CodeNode 节点检查器与端口配置

## 节点可编辑字段

除自动生成且不可修改的节点 ID 外，检查器支持编辑：

1. 节点名称；
2. 制作提示词；
3. 内嵌代码；
4. 输入端口数量、名称和支持类型；
5. 输出端口数量、名称和输出类型；
6. 节点语言。

端口数量范围为 0～32。支持类型包括自动、整数、小数、文本、布尔、对象、数组和任意；输出端口必须选择明确类型或“任意”。删除端口时，与该端口关联的边也会一并移除。

## 连线类型规则

- 输入端口为“自动”时，第一次连接到输出端口会继承输出端口类型；
- 两端任一类型为“任意”时允许连接；
- 其他情况下必须类型完全一致，否则拒绝连接；
- 自适应后的输入类型会写回节点数据和 BuildRequest。

## 制作模式

检查器“制作节点”按钮现在明确调用 `buildSelected('node')`，生成 `action: build-node`。工具栏选择“制作成程序”生成 `action: build-program`。Markdown frontmatter 携带该 action，MCP 请求队列据此显示“请求制作成节点”或“请求制作成程序”。

此前误判的根因是检查器按钮没有绑定事件，节点仍使用默认 `program` 模式；并非 MCP 队列解析器本身无法识别。

## 验收

```powershell
node .\codenode\scripts\test-canvas-contract.mjs
node .\codenode\scripts\test-mcp.mjs
```

画布契约测试固定检查制作按钮绑定、检查器字段、端口配置入口和自动类型继承分支；MCP 测试同时覆盖 `build-node` 与 `build-program`。

## 请求队列手动删除

每条待处理请求提供独立“删除”按钮。用户确认后，页面调用本地 MCP Bridge 的受限 `DELETE /markdown?filename=...` 接口；服务端仅允许删除收件箱中的安全 `.md` 文件名，并同步移除对应的队列序号元数据。已处理请求、生成结果和输出程序不会被该操作删除。
