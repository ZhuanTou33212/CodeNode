# 全局联动调度与子任务配额预警

本次将子任务调度器和模型请求队列联动，并在主 Agent 的模型上下文中加入额度预警。未实现自动任务图派发，也未改变失败任务、用户取消或未知副作用的自动重跑规则。

## 配置与执行

- 默认并发 4：一个全局数值同时限制子任务槽位和模型请求队列，范围 1–8。共享工作区写任务仍独占执行；不同运行共用模型请求队列。
- 默认每次运行累计启动 24 个子任务，范围 1–100；单批默认 8 个，范围 1–32。
- 默认预警阈值 75%，范围 10–95%。阈值向上取整，因此 24 个额度在第 18 个启动后预警。
- 设置入口为“设置 → 常规 → 全局调度”。工厂默认值和范围集中在 `config/ui.scheduling.json`。用户设置原子保存到 `$CODENODE_HOME/agent-scheduling.json`，默认 `~/.codenode/agent-scheduling.json`，桌面和命令行共用。项目属性不覆盖全局调度配置。
- 未保存用户级设置时，兼容全局 `agent.scheduling.concurrency` 与旧 `agent.subagent.max_concurrent_tasks`，其中新键优先。其余累计数量、批次数和阈值兼容全局属性文件。
- 有 Agent 或模型请求运行时，设置入口和主进程拒绝修改。队列自身也支持安全扩容与缩容，缩容不取消在途请求，等其退出后再放行等待项。

## 预警与额度恢复

主 Agent 在上下文压缩及裁剪之后、下一次模型请求之前读取真实累计数。在达到阈值后更新一条机器提示，给出已用／上限／剩余数量，要求收敛规划、优先必要验证、如实列出完成、未完成和阻塞项；额度耗尽时要求停止新增委派。压缩丢弃提示后，下次请求会重新注入当前数值。提示不传给子 Agent，也不增加额度或跳过验收、审批、Token 和费用限制。

失败或启动后取消的任务计入累计额度；只排队、未启动就取消的任务不计入。并发槽位与累计额度独立，执行实际退出后释放。累计启动数与任务视图一起持久化，但独立于历史视图保留条数，避免失败记录被清理后，重启恢复少计额度。旧格式按保留的 `startedAt` 记录兼容迁移；已经被旧版本清理的历史记录无法补算。

预警是收敛提示，不保证模型遵从，也不强制终止已运行的子任务；硬上限继续由管理器执行。

## 验证

- `test:scheduling`：全局保存、跨进程读取、项目覆盖边界、双层并发一致性、非法配置及损坏文件保留；队列扩缩容、FIFO、取消和重复释放；真实 Agent 工具循环在阈值前无提示、阈值后只有一条、耗尽时更新数值；失败计数、超额拒绝及重启恢复。
- `test:scheduling-ui`：真实 IPC 保存与重开、跨项目配置、运行请求守卫；昼夜主题控件和值一致，切换时保留会话、输入草稿、模型及侧栏状态。
- 已通过前端构建、主进程与脚本 JS 类型检查，以及子代理、隔离、任务视图、结果信封、进度、请求预算、请求可靠性、信息完整性、普通工具自动执行、恢复、压缩、生产门禁、命令行、角色技能、工作树、成本和 IPC 相关回归。
