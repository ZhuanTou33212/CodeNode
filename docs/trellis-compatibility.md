# CodeNode 兼容 Trellis

读取已有 Trellis 工程、选择当前对话任务、展示 PRD/规范/清单、向主 Agent 与子 Agent 提供任务资料、持久化 Task 与 Run 的关联，并在重新打开工程后恢复选择。现已提供受控状态/日志/规范写回及绑定真实角色动作的画布流程。执行、权限、恢复及验证仍由 CodeNode 管理。

## 使用

打开包含 `.trellis/` 的项目，在对话输入框上方展开“兼容 Trellis”，选择任务。展开“本次使用的规范和资料”可检查原文、角色范围与 SHA-256 指纹。发送普通消息即可交给当前 Agent 执行。切换对话可分别绑定不同任务；选择“不绑定任务”解除该对话的绑定。重新读取资料会读取当前文件；显式续跑使用原 Run 保存的资料快照。

“关联运行与验证证据”列出最近 200 次运行中的关联记录。运行完成、失败、取消、预算结束均不自动修改 Trellis 任务状态。验证报告展示实际命令、范围与结果；代码/依赖/配置或任务资料变化后，旧通过证据失效。局部代码检查不代表全部 PRD 验收通过。

展开“任务写回与画布流程”，选择任务状态、工作日志或规范建议，填写来源/证据后点击“预览修改”。预览展示每个文件的原指纹、修改前后全文；只有“应用预览修改”执行写回。`completed` 必须勾选明确的人工 PRD 验收确认并填写证据，不从 Agent 结束状态推断完成。

日志写入已有 `.trellis/workspace/<developer>/journal-N.md`，并维护索引的已确认自动区段；保留原日志、人工笔记与未知内容。识别三组 `@@@auto` 标记及会话编号，遵循上游 `max_journal_lines`（未声明时 2000 行）轮转。未知结构、损坏编号或不支持的配置保持只读。规范建议只编辑已加载的现有 `.trellis/spec/*.md`，须填写来源和适用范围。

多文件写入的原文、候选内容、指纹和状态持久保存在 `.codenode/trellis-transactions/`。应用前校验全部来源，逐文件提交前再次校验并原子替换。中断/部分失败不会报告全部成功；重开后从“未结束事务”选择建议，可恢复剩余写入或按指纹回滚已写部分。恢复不重复追加日志，回滚不覆盖外部修改。外部程序不遵守 CodeNode 锁时仍存在检查与替换之间的竞态窗口，此协议是乐观冲突检测和可恢复提交，不是跨工具原子事务；发生外部冲突需先核对文件再恢复。

“添加任务执行流程”向当前画布追加可撤销的准备→实现→验证→审查与收尾 DAG，分别显式绑定 explorer/builder/verifier/reviewer、任务路径和保存的资料快照。在画布运行工作流后，现有主进程执行器负责依赖、真实模型/工具调用、持久准备/结算及未知副作用复核。角色工具白名单和只读权限实际生效；角色阶段当前使用 CodeNode 自研 Agent，外部 ACP 后端明确拒绝此流程以避免误称角色约束已生效。节点名不决定动作，阶段完成不代表全部 PRD 验收通过，也不自动写回状态/日志。资料变化后停止沿用画布，核对并重新生成；节点位置改变不会更换资料版本。

## 支持的结构

参考 Trellis CLI `0.6.17`，核对固定上游提交 [`f089cb3286071199e84118dee86b6d76aab032f1`](https://github.com/mindfold-ai/Trellis/tree/f089cb3286071199e84118dee86b6d76aab032f1)。按结构识别兼容性，不宣称支持所有版本。

| 文件 | 用途 |
| --- | --- |
| `.trellis/tasks/<目录>/task.json` | 原任务 ID、标题、原状态；写回完整保留未知字段 |
| 同目录 `prd.md` | 所有角色的需求与验收来源 |
| 同目录 `design.md`、`implement.md` | 可选设计与实现计划 |
| 同目录 `implement.jsonl`、`check.jsonl` | 每行 `{ "file": "仓库相对路径", "reason": "用途" }`；跳过 `_example` 示例 |
| `.trellis/spec/**/index.md` | 显式加载基础规范索引 |
| JSONL 中的仓库相对文件 | 适用专项规范与研究资料 |

主 Agent 和 explorer 接收公共资料及两阶段索引/资料，builder 接收实现清单，verifier/reviewer 接收检查清单。跨角色共用一个 Run 快照，隔离工作树不重新读取主工作树的新版本资料。未列入清单且非基础索引的规范不自动推定适用，应由任务清单明确引用。没有任务绑定时不改变原提示词。

适配层位于 `electron/trellis/`；文件访问、事务及绑定验证在主进程，React 通过 IPC 请求读取、预览、应用、恢复和生成画布。参考格式与资源安全上限集中在 `config/trellis.compatibility.json`，属于内部兼容边界，并非新增用户设置。任务资料加入 `promptContext.cjs` 的动态预算保底段落，超出预算会明确停止，规则不被静默裁剪。画布角色复用已有成本与模型设置中的角色模型、轮次、总 Token 与输出额度；没有配置角色模型时沿用当前模型。续跑沿用原角色，不能提升为主 Agent 权限。

缺少 PRD、规范目录、阶段清单，清单为空/损坏、未知任务状态、必要文件过大或不安全时显示诊断并阻止选定任务的执行。可以修复文件或解除绑定后继续。归档任务、上游当前任务指针及不带已验证标记的其他日志格式暂未纳入支持范围。

## 数据归属与写入边界

- `.trellis/` 始终是任务需求与规范的唯一来源。适配器仅支持已确认格式的状态、日志与规范写回；不创建/归档任务或更改上游当前任务指针。状态写回保留原 JSON 的未知字段、格式及其余字节，只替换顶层 status 与状态转换时已存在的 completedAt。
- `.codenode/trellis.json` 只保存稳定对话标识与任务路径；使用既有原子写入及指纹冲突检查，不复制 PRD 作为另一份权威需求。
- Run 的 `trellis_context` 事件保存实际资料快照与指纹，记录与原始工具证据保存在 CodeNode 现有运行存储。资料内容按既有 Run 日志脱敏机制保存。
- CodeNode 现有工具依然可以按用户授权编辑项目文件。兼容适配器的受控写回独立于通用 Agent 文件工具；未识别格式保持只读，不能借此认定整个 Agent 对项目没有写权限。

## 验证与后续阶段

`npm run test:trellis` 使用独立编写的固定版本结构样例，验证真实桌面主 Agent 请求、四类真实子 Agent 分派、缺失/损坏/预算诊断、路径及链接边界、上游文件不变、关联恢复、续跑快照及验证失效。

`npm run test:trellis-ui` 验证真实 main/preload/renderer、选择与资料展示、昼夜功能一致、主题切换保持草稿/会话/模型/侧栏，以及保存工程重开后的任务恢复。可设置 `CODENODE_PACKAGED_ASAR` 验证实际交付包。

`npm run test:trellis-write-canvas` 验证 JSON 字节保留、指纹冲突、人工验收、日志/索引/轮转、注入失败后的跨实例恢复与回滚、规范建议，以及真实 project:workflow-execute DAG 分派和角色工具权限。UI 测试同时覆盖两主题预览/应用、切换主题保持预览、日志更新、生成绑定流程和撤销/重做；可用同一入口检查交付包。

已完成首个交付闭环、受控写回及显式画布阶段执行。PRD 验收项逐项自动绑定证据、归档任务及独立 CLI 集成仍未实现；当前完成确认明确记录为人工证据，不伪装成机器验收。

独立实现格式互操作，未复制或链接 Trellis 源码、Skills、提示词或模板。Trellis 的工作流设计为本功能提供启发。CodeNode 与 Trellis 无官方合作或认可关系；此文描述兼容实现范围。
