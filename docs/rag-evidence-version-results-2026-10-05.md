# 最终证据版本与写后失效保护

本轮修复最终引用与事实判定仍可能消费写前源码的问题，目标仍保持进行中。

## 统一证据过滤

`electron/rag/evidenceHistory.cjs` 为引用位置校验和事实支持性判定提供同一份当前证据视图，原始审计记录不改写。

- 已知文件写入、编辑、重命名、删除或 patch 使目标路径的旧读取与 RAG 片段失效。
- 未知路径的潜在写入、Shell、项目执行、异步任务等采用保守失效，需要重新读取。
- 明确回执 `executed=false` 不按已执行操作处理；其他失败写入不能凭失败标记推定没有副作用。
- 新读取观察到版本变化时，旧版本证据失效。首次有哈希的深读也替代同路径的无版本 RAG 来源。
- 同一标量 key 的新观察替代旧值；画布变化使旧标量观察失效。
- 文件路径在 Windows 按大小写不敏感处理，标量 key 保持原始身份。

所有来源失效后，旧引用仍会进入校验并判为 invalid，不能以“没有来源，因此无需校验”绕过保护。重新读取后可恢复新的合法引用。

## 判定缓存

原缓存只绑定答案文本；相同答案在证据变化后可能复用旧支持判定。现以答案、实际选择的证据正文、范围/截断状态与文件版本哈希构造 SHA-256 缓存键。

证据未变时保留去重；文件版本或正文变化、写入后失效以及重新读取都改变缓存身份。

## 验证

`scripts/core/rag-evidence-history-test.cjs` 覆盖按路径失效、其他文件保留、重新读取恢复、新版本替代、未知外部副作用、失败写入、明确未执行回执、RAG 来源过滤、无来源绕过、审计历史不可变、缓存版本身份和新标量替代。

既有来源位置、深读证据、事实支持性与运行级 enforce/warn 回归也复验。

## 边界

这是工具历史与已观察版本的保护，不是任意外部编辑的即时检测：用户或外部进程修改后，若没有新的读取或变更通知，仍需进一步实时版本核验。

保守清理可能让纯只读委派也需要重新读取；尚未按每个子任务的已验证权限进一步精细化。历史版本说明需要明确版本出处，不能把写前证据当作当前路径证据。

独立人审、新未见验收、高召回与完整任务达成率、更多语言及文档边界仍未完成；本轮不能标记全部问题完成。
