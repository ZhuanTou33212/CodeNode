# Agent 回复逐字显示

后端已有 SSE 增量回调，经 `agent:delta` 实时写入会话；本次在回复气泡中加入独立的显示缓冲，让一个分片内的文字逐字呈现。完整收到的文本仍直接写入会话、保存及后续模型上下文，不因显示进度被截短，也不额外调用模型。

## 设置与行为

- “设置 → 常规 → 回复显示”提供“逐字显示 Agent 回复”开关及速度设置。默认开启、60 字／秒，范围 20–160。
- 默认值集中于 `config/ui.defaults.json`，速度范围和 3 秒长分片追赶策略集中于 `config/ui.output.json`；界面偏好自动保存在现有 `codenode.uiPreferences` 中，昼夜共用。旧偏好自动补齐新默认值。
- 正在生成且已收到正文时显示“输出中”；逐字阶段有细光标，读屏不会读出光标字符。历史消息、用户消息和压缩摘要不重播打字动画。
- 按 Unicode 字符簇推进，中文、emoji、组合字符不会按 UTF-16 半个字符截断；追加分片时重分割末尾字符簇。较长分片加快追赶，避免缓冲造成几分钟的额外等待，因此长段落的瞬时速度可能高于设置值。
- `content_reset` 增加渲染版本，清空旧显示队列；停止、失败、截断、关闭逐字开关时立即显示已经收到的正文并停止动画。切换会话重新挂载对应消息，避免旧响应跨会话泄漏。完成事件不会吞掉尚未显示的尾部。
- 回复增长时跟随底部；用户滚动阅读较早内容时不被逐字刷新强行拉回，新用户消息重新开启跟随。
- 系统“减少动画”偏好生效时直接显示增量，不播放打字和光标动画。

严格来源／事实核验模式仍在后端核验通过后交付正文；这种模式开始显示较晚，但通过后的正文仍可逐字呈现。显示设置不关闭核验门槛，也不改变服务端生成速度。

## 验证

`test:text-reveal` 覆盖逐字推进、连续追加、Unicode／代理项边界、同前缀响应重置、完整刷新、历史消息、长分片追赶及偏好规范化。

`test:streaming-ui` 使用真实 Agent、延迟 SSE、IPC 和会话存储，核对收到文字与显示文字存在逐步推进、最后逐字相等；覆盖重试撤回、停止、失败、历史切换、开关／速度持久化及原生减少动画偏好。昼夜主题共用控件和显示逻辑，切换时保留会话、模型、草稿及侧栏状态。

相关前端、流累加、断流恢复、异常、状态、插话、会话、截断和来源核验回归，以及紧凑对话／调度设置 UI 和主进程／脚本类型检查需通过后交付。交付使用独立源码及打包暂存目录验收，再覆盖固定 `release/win-unpacked`，并清理隔离数据。
