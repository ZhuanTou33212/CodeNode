# 子任务 Attempt 与受控文件补偿

本次新增同一任务 ID 下重做整个子任务的入口。请求级 HTTP 重试继续使用已有共享请求重试额度；整任务重做增加独立 Attempt，并保留以前的结果及副作用摘要。

## 状态与额度

逻辑任务 `taskId` 保持不变，顶层状态表示最新一次执行。`attempts[]` 保留每次的序号、独立 `executionId`、排队／开始／结束时间、状态、结果摘要与摘要截断数量、结果指纹、核验态、工作树、用量、文件前后指纹和补偿结果。历史摘要最多 8000 字，完整文件前像保存在受保护的逐次副作用记录中；模型上下文仅接收短卡，不重复注入全部历史。

| 配额 | 默认 | 范围 | 计数规则 |
| --- | --- | --- | --- |
| 逻辑子任务 | 24 | 1–100 | 新任务首次进入运行状态；失败或启动后取消不归还 |
| 单任务 Attempt | 3 | 1–10 | 含首次，显式重做时分配下一版本 |
| 全局 Attempt | 72 | 1–1000 | 各任务实际进入运行状态的尝试总数；失败或启动后取消不归还 |
| 子任务／模型请求并发 | 4 | 1–8 | 同一全局数值联动；共享工作区写任务及补偿独占 |

默认单批仍为 8；逻辑任务或 Attempt 达到 75% 时均可触发主 Agent 的收敛提示。设置集中在“设置 → 常规 → 全局调度”，由 `config/ui.scheduling.json` 提供默认值和边界，用户级 JSON 原子持久化。旧四项设置读取时补齐两个新默认值，不丢失原值。

逻辑任务数与实际启动尝试数分别持久化，跨重启重建。可重做任务的身份和历史受保护，不会因额外的配额拒绝记录而被历史保留策略淘汰。队列槽位只在本地执行 Promise 退出后释放；发出取消信号不立即释放，外部效果也不因此被视为撤销。

## 重做流程

1. 主 Agent 调用 `inspect_subagent_retry(taskId)`，只核对任务状态、额度、依赖、角色模型、文件版本及副作用，得到 `executionId`、`planDigest`、文件动作和 `canRetry`。
2. 只有上次已结算、处于终态且没有在途下游任务时可重做。普通 `delegate_task` 复用 ID 仍会被拒绝。
3. 主 Agent 调用 `retry_subagent_task(taskId, expectedExecutionId, planDigest, reason)`，绑定确切旧执行和计划。请求重复、旧版本或指纹漂移被拒绝。
4. 取得补偿独占槽位及文件租约后，列出文件动作申请 HIGH 级批准；已取消任务即使没有文件改动也须新批准。未批准时不恢复／删除文件，不启动新 Attempt。
5. 再核对指纹，撤回旧候选结果并使下游需复核，然后执行文件补偿。只有补偿完整且写后核验通过，才注册新的 Attempt，并沿用原目标、角色、输入、依赖、验收条件、隔离和预算要求；重做原因进入子 Agent 上下文。
6. 新 Attempt 使用独立历史，结果重新成为候选，不能沿用旧确认或 verifier 结论。所有新请求仍消耗父 Run 的实际 Token／费用预算，补偿不退还已经消耗的成本。

## 补偿边界

当前自动补偿只覆盖 `write_file`、`edit_file` 的本地普通文件内容：首次写前记录前像和强 SHA-256，工具写入绑定读取版本；同一 Attempt 内多次写保存最早前像和最后后像。补偿恢复原内容，或删除该 Attempt 新建的文件；不递归删除目录。

审批后和写入前重新检查指纹；目标内容被后续修改、前像损坏、路径越界、符号链接、硬链接、非普通文件、过大的文件或副作用记录均会阻止自动操作。文件上限为 8 MiB，逐次记录上限为 16 MiB。空文件与二进制前像可恢复，但不声称恢复全部权限、时间戳或其他文件系统元数据。

补偿记录采用 prepared → completed／needs_review；中途失败时不启动新子代理。再次核对时，已经恢复的文件可以跳过，剩余项须继续通过指纹和前像核验，不能强制覆盖。

shell、画布、批量画布／资产操作、外部服务及未结算／未知副作用不做通用补偿，必须先复核，重做入口不会自行跳过这些记录。已合入主工作树的代码也不自动撤销，需另建修复任务。没有逐次记录的旧任务，以及未建立逐次记录就结束的准备阶段任务，保留旧视图但不能通过该入口重做。

工作树隔离任务在原受管工作树内补偿并复用该树，不触碰主工作树。该机制是单个 Run 管理器的受控重做，不是跨进程分布式任务调度器。

## 验证

- `test:subagent-attempts` 通过真实 Agent 文件工具循环验证同 ID 三次 Attempt、恢复／删除、审批拒绝、旧请求拒绝、历史／计数／跨实例恢复、费用归属及配额拒绝不淘汰有效历史。
- 负向用例覆盖同大小／时间戳但内容变化、审批期间漂移、模型或上游不可用、外部／未结算／未知副作用、补偿中途失败、空／二进制前像、越界记录、全局尝试上限、运行／取消期间禁止重做及真正退出后释放槽位。
- Git 工作树用例验证补偿和重做复用原隔离目录，主工作树保持不变。
- `test:scheduling-ui` 验证两个新设置真实 IPC 保存、重开／跨项目、历史展开和昼夜一致性；切换主题保留会话、输入草稿、模型与侧栏。
- 主进程／脚本类型检查及子代理、输出契约、恢复、Run 回滚、幂等、信息完整性和工具上下文开销回归均须通过后交付。
