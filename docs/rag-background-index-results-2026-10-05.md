# RAG 后台索引与结果流背压

## 实现

生产桌面与 headless Agent 的 `rag.index_worker` 默认开启。后台 worker 执行目录扫描、文本/Office/PDF 文字层提取、AST 分块、词频结构和关系图构建。向量服务、模型请求、预算与取消作用域仍由主执行链管理；API Key 和模型回调不发送到扫描 worker。

同步 `refresh()` 作为离线诊断接口保留。显式设置 `rag.index_worker=false` 才使用同步检索刷新，结果标记 mode=sync。worker 失败不会自动切回主线程阻塞扫描。

worker 保留增量文件缓存，未变化文件不重新解析；主线程收到变化条目和关系图快照。每批最多 16 个文件条目，主线程让出事件循环后确认接收，worker 才发送下一批，避免密集消息挤占主循环。

## 一致性与取消

- 同一索引的刷新串行提交。
- 明确失效标记即使文件大小/mtime 不变也会重新读取。
- 扫描期间发生修改时，过期结果不提交，强制重新同步；连续三次不稳定后返回明确错误。
- 完成回传与主线程提交之间取消，也不提交部分缓存。下一次刷新会重新同步，避免 worker 已更新、主缓存却漏文件。
- 排队调用取消不会终止别人的扫描；运行中的调用取消会终止其 worker 请求。
- worker 错误、超时或提前退出不会被记为完成，也不触发静默同步降级。
- 根缓存、依赖与敏感文件仍过滤；被忽略的资源文件不再提前耗尽有效文件配额。

## 打包

worker 需要真实文件路径，部署到 app.asar.unpacked。RAG、内存向量与嵌入基础依赖、文件核心及 TypeScript 解包供其使用。

暂存包测试发现 glob 匹配曾通过 shared 工具辅助间接加载审批模块，导致 worker 的 MODULE_NOT_FOUND。现直接使用 fsCore 的同一个纯 glob 实现，避免引入审批状态或增加无关权限。

实际 ASAR 测试覆盖真实解包 worker、TypeScript AST、关系图快照、DOCX 正文与 src/cache 业务目录。不能仅以开发模式通过当作打包成功。

## 规模与响应实测

本机 Node/Electron 环境，合成真实文件，每份 TypeScript 有 100 个局部声明。数据创建在计时前完成。

| 测试范围 | 结果 |
| --- | --- |
| 800 个 TS 文件 | 扫描与 AST 约 0.9 秒，主线程心跳持续可运行 |
| 5000 个 TS 文件（实际索引 5002 文件） | 整条检索约 4.28 秒 |
| 5000 文件提交阶段 | 约 6 ms |
| 5000 文件词法评分 | 约 16 ms |
| 无背压时完整链最大心跳间隔 | 约 225 ms |
| 加入背压后最大心跳间隔 | 约 39 ms |

首次测试只观察 worker 忙碌期间的心跳，漏掉了最终提交/评分之后的延迟，因此其 24 ms 结果不能证明完整链响应。测试已补上完成后的延迟心跳，定位并修复回传消息洪峰。

上述是单次本机测量，不是跨机器性能承诺。尚未验证挂住的网络盘原生 I/O 能立即物理停止，也没有以此宣称任意规模项目已解决。worker 有 512 MiB V8 堆保护与 120 秒任务超时；非常大的图、常驻内存与候选排序仍需继续优化。

- `scripts/rag-packaged-worker-test.cjs`：实际 ASAR worker 依赖闭包。

- `out/rag-worker-main-phases.log`：提交/评分计时。
- `out/rag-worker-5000-backpressure.log`：背压后的完整链结果。

目标仍在进行中：独立人审、新的未见验收、稳定高召回与完整任务达成率、更多语言和文档边界等未完成，不能因本轮性能改进标记全部完成。
