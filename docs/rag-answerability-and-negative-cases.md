# 核心事实证据链与 30 道相似无答案用例

## 本轮范围

已定义 30 道开发负样本，见 `scripts/fixtures/rag-adversarial-negatives-v1.json`。每题包含问题、必须证实的事实、缺失/矛盾原因、相似来源和错误类型，覆盖算法偷换、数值错误、条件反转、虚构外部后端、跨文件关系拼接等。

来源是冻结的 v1 模拟业务语料，不是采集到的真实用户问题。负样本与语料 SHA-256 固定在 `rag-adversarial-lock-v1.json`。它们是作者可见的开发集；不能将它们称为未污染验收集。

不存在的实现不应被编造。例如“缓存如何实现 LRU”，现有 TTL 代码只能用于纠正前提，不足以回答 LRU 实现过程。“是否支持 LRU”是不同类型的问题：若来源明确说明不支持，可以有证据地回答否定；本组实现问题的期望是纠正前提或拒绝给出不存在的实现。

## answerable 的新含义

`level/topCoverage/basis/retrievalRelevant` 表示检索相关性，不证明问题可回答。

| 状态 | answerable | 含义 |
| --- | --- | --- |
| supported | true | 问题全部核心事实通过模型证据判定，且原文引句存在 |
| insufficient | false | 已判定，至少一项核心事实缺失或矛盾 |
| unknown / unverified | false | 没有执行校验、校验失败、证据过预算或判定格式不合法 |

缺证据不等于功能不存在；unknown 不等于拒答正确。Agent 应继续检索、深读或明确说明无法判断。

默认生产配置 `agent.rag.answerability=verify`：每次检索先仅根据问题提取全部必要事实，再把这些事实交给来源判定模型。先提取事实时不展示检索片段，减少模型顺着片段遗漏问题要求的风险。最多 12 项事实，4000 字符问题、24000 字符证据；不满足约束就返回 unknown。

只有每项都为 supported，且每个引句都出现在指定来源中，才置 `answerable/evidenceVerified=true`。数值、条件、否定、实现存在性和跨文件关系均在判定提示中要求检查。没有原文证据、遗漏事实、重复 ID、非法 JSON、超时或取消不允许通过。

文件和标量都不能依靠词语匹配直接升级为 answerable。标量精确 key 只证明取到了该值，不自动证明它回答整个复合问题。纯标量或混合来源也走相同校验。

模型调用走主 Agent 现有请求、重试、token/费用预算及取消路径。每次检索通常额外产生两次模型调用，混合来源可能再校验合并后的证据。设置 `agent.rag.answerability=off` 可以关闭调用，但状态保持未校验，不恢复词法匹配即允许回答的行为。

此判定仍是模型判断，不是形式化证明。原文引用存在只验证来源真实性，不能确保引句逻辑上支持结论；提取事实也可能漏项。需要真实模型及人工标注评测验证准确率。

## 验证与指标

```powershell
npm run test:rag-answerability
npm run test:rag-benchmark
```

回归检查 30 题都能召回相关候选，但不凭词法升级为可回答；另有正样本通过、部分事实缺失、矛盾、伪造引句、格式错误、运行时隔离及真实 Agent 调用链（使用脚本模型替身）测试。

这些测试验证契约和失败处理，未测真实判定模型准确率。离线检索评测现在同时记录 `positiveAnswerableRate` 和 `verificationCoverage`；没有模型时两者为 0，负样本误判率为 0 不得解释成拒答质量改善。新 `answerable` 指标与旧词法指标不可直接比较。
