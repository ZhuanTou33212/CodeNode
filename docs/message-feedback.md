# 消息复制与回答反馈

用户消息和 Agent 回答的文字可以选中并使用系统复制。每条普通消息也提供“复制”，由主进程写入完整原文到系统剪贴板；成功后显示“已复制”，失败时明确提示。渲染层不需要获得浏览器剪贴板权限。

“有帮助”保存当前回答及用户问题、对话/画布来源和工具摘要，作为同一对话后续回答的表达与相关性参考。“需改进”展开简短表单，用户填写具体意见并提交后保存；下一轮自研 Agent 与外部后端会收到该对话的最近反馈资料。模型仍需按当前需求执行，不承诺每次都正确修复，也不会自动触发额外模型调用。

评价状态从项目 `.codenode/feedback.jsonl` 恢复，关闭重开仍可见。修改评价采用最新记录，已替换的意见不会继续作为该回答的有效反馈；导出也只使用各回答的最新评价。保存失败不会显示成功状态，重复相同评价不会重复追加。资料按现有规则脱敏，存储使用锁与原子审核更新，并拒绝链接路径；运行时反馈不提交到源码仓库。

反馈只限于同一稳定对话标识，最多最近三个回答；内容及意见截取后形成有限的资料段落。赞同不代表事实正确、工具成功或任务验收通过；反馈不能改变工具权限，也不会自动写入长期记忆或声称已经训练模型。反馈候选仍可通过既有导出和人工审核机制用于评测。

验证：`test:message-actions-ui` 检查真实文字选区、主进程剪贴板、两主题、表单保存、评价更改和重开恢复；`test:feedback-store` 验证持久化及对话隔离；`test:trellis` 通过实际聊天处理器与模型请求验证用户修正意见送达。
